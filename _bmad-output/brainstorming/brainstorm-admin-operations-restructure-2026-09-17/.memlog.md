- (technique by coach) started First Principles Thinking
- (idea by coach) Admin exists to notice, understand, and safely change exceptional system state—not to duplicate the consumer product.
- (idea by coach) Every admin page should answer one operator question and expose one next responsible action.
- (idea by coach) Read truth before permitting action; investigation context must precede controls.
- (idea by coach) Order agreement, Work execution, Payment Obligation, Evidence, Dispute, and Hold remain visibly separate aggregates.
- (idea by coach) The admin may display incomplete implementation honestly instead of simulating green success.
- (idea by coach) Navigation should follow operator work: attention, investigation, intervention, monitoring, governance.
- (idea by coach) A universal Inspector should accept any supported reference and resolve its related aggregate graph.
- (idea by coach) Triage should contain pointers to work, not miniature copies of every domain page.
- (idea by coach) Operational counts must name their cohort and evidence class.
- (idea by coach) Fixture, sandbox, training, and genuine records require persistent visual classification.
- (idea by coach) Consumer theming and admin theming can diverge because their jobs, density, and risk differ.
- (idea by coach) Admin UI should depend on stable view projections, not concrete module models.
- (idea by coach) Unimplemented actions should not be rendered as clickable controls.
- (idea by coach) Read-only pages can ship before command services, provided the UI labels their limits.
- (idea by coach) Every mutation must state actor, reason, scope, expected effect, and recovery path.
- (idea by coach) Corrections append events; the interface never implies that history was erased.
- (idea by coach) Search should lead with human references and correlation IDs, not internal database IDs.
- (idea by coach) Domain work in parallel requires versioned prop/view contracts so frontend and backend can evolve independently.
- (idea by coach) Empty state, unavailable state, permission-denied state, and load-failure state must be distinct.
- (idea by coach) Admin authentication and authorization are foundational, not a later polish task.
- (idea by coach) Actions need deny-by-default authorization even if fixture data is disposable.
- (idea by coach) The first useful admin release can be read-only and still materially help domain development.
- (idea by coach) The primary success measure is faster diagnosis with fewer mistaken interventions, not dashboard engagement.
- (idea by coach) Blueprint editing belongs outside incident operations because its intent and risk profile differ.
- (idea by coach) A page should not own both catalog authoring and live record remediation.
- (idea by coach) The admin shell should advertise environment and dataset class persistently.

- (technique by coach) started Morphological Analysis
- (idea by coach) Triage source can be a union projection over reviews, disputes, holds, safety, failed events, and support cases.
- (idea by coach) Queue entries can share a stable envelope: id, kind, priority, title, subject reference, cohort, age, owner, status, next action.
- (idea by coach) Inspector search can accept order reference, user reference, payment obligation, correlation ID, or event ID.
- (idea by coach) Inspector view can use summary header plus separate aggregate rails rather than one merged timeline.
- (idea by coach) Cross-domain timeline items can share actor/time/type/summary/correlation while preserving domain-specific payload links.
- (idea by coach) Admin list pages can standardize filters through URL query state for shareable views.
- (idea by coach) List pages can standardize columns but keep domain-owned status vocabulary.
- (idea by coach) Read projections can return capability flags controlling which actions render.
- (idea by coach) Unavailable capabilities can show implementation status only in development environments, not to normal operators.
- (idea by coach) High-risk actions can use a consistent drawer: scope, consequence, evidence, reason, confirmation.
- (idea by coach) Low-risk navigation actions can remain inline while mutations move to guarded drawers.
- (idea by coach) Marketplace pages can be read-mostly registries feeding the Inspector.
- (idea by coach) Blueprint pages can use draft/published/versioned states independent of live marketplace records.
- (idea by coach) Work template nodes can carry evidence requirements but never impersonate executed Work events.
- (idea by coach) Deal Chain blueprints can describe dependencies without claiming active orchestration until the module exists.
- (idea by coach) Taxonomy can distinguish governed catalog records from locally edited canvas drafts.
- (idea by coach) System Health can combine outbox, inbox, webhook delivery, and provider-event reconciliation as separate tabs.
- (idea by coach) Audit can be a universal side panel reachable from any aggregate rather than a standalone dumping ground only.
- (idea by coach) Recovery can be a small evidence register with owner, target, last rehearsal, result, and next due date.
- (idea by coach) Operational metrics can begin with counts and aging before attempting funnels or revenue.
- (idea by coach) Fixture scenarios can carry deterministic references so mock-derived UI states map to seed data.
- (idea by coach) Projection interfaces can be implemented first with query-builder adapters, then replaced without changing React props.
- (idea by coach) Admin routes can use named routes and Inertia pages: queue, identity-reviews, inspector, disputes, system-health, orders, listings, tenders, accounts, financials, blueprints.
- (idea by coach) Sidebar badges should come from a small shared navigation-count projection, not page constants.
- (idea by coach) Global admin search can resolve references and route to Inspector instead of filtering the current page only.
- (idea by coach) Environment banner can show local/test/capstone plus cohort scope and last refresh.
- (decision by coach) MoSCoW MUST: protect all admin routes with explicit admin authentication/authorization before exposing real data.
- (decision by coach) MoSCoW MUST: restructure navigation around Triage, Identity Review, Inspector, Disputes & Holds, System Health, Marketplace registries, and Blueprint governance.
- (decision by coach) MoSCoW MUST: reduce Triage to a queue envelope and route all detailed investigation to one universal Inspector.
- (decision by coach) MoSCoW MUST: remove or visibly disable fake local-only actions; no alert, timeout, or React-state mutation may masquerade as an operational command.
- (decision by coach) MoSCoW MUST: retain explicit fixture/sandbox/training/genuine classification and environment context on every operational surface.
- (decision by coach) MoSCoW MUST: define stable Inertia projection contracts before wiring backend queries, keeping Order, Work, Payment, Evidence, Dispute, and Hold separate.
- (decision by coach) MoSCoW SHOULD: make Accounts, Listings, Orders, Tenders, Financials, and Catalog pages read-mostly registries that deep-link to Inspector.
- (decision by coach) MoSCoW SHOULD: preserve shadcn admin styling and spend design effort on density, hierarchy, states, and safe action flows rather than consumer Glovo theming.
- (decision by coach) MoSCoW SHOULD: implement read projections before command services, beginning with navigation counts, triage queue, and inspector summary/timelines.
- (decision by coach) MoSCoW COULD: add saved filters, keyboard search, mobile read-only incident visibility, and investigation notebooks after the core routes stabilize.
- (decision by coach) MoSCoW WON'T NOW: port consumer mock pages, implement TrustSupport/Operations commands, claim live integrations, build revenue funnels, or persist blueprint edits.
- (insight by coach) The admin restructure is a contract-design task first: stable operator questions and projections let the UI mature independently while domain modules are still moving.
- (insight by coach) The safest next increment is navigation and truthfulness, not data wiring: establish page ownership, universal Inspector routing, dataset labels, and honest disabled states before replacing fixtures.
- (insight by coach) Triage and Inspector form the operational spine: Triage says what needs attention; Inspector explains what happened; domain pages provide discovery and context; guarded drawers eventually perform actions.
