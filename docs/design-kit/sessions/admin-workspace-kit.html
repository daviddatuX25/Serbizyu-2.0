Foundations

Six contracts every admin page follows. Built from the existing shadcn components; patterns borrowed from Shadcn Admin.

1Theme

One token source: the light theme in app.css.

NavyStructure
WhiteSurfaces
MangoAttention
CanvasBackground
  • Status colours stay semantic, never brand.
  • Dark mode is an option, not the identity.

2Shell

Five daily destinations; specialist tools below.

  • Inbox · Orders · Marketplace · People · Payments.
  • Governance, System, Audit: permission-filtered.
  • Server-derived environment and data cohort in the top bar.
  • Global search (⌘K) opens records directly.

3Lists

Answer “which record do I open?”

  • Saved views with counts instead of metric cards.
  • Search, a few filters, compact rows, one Open action.
  • Each row: reference, people, who it waits on, age.

4Records

Answer “what happened, and what may I do?”

  • Identity and parties first.
  • Agreement, Work, Payment and Case as separate rails.
  • Current responsibility, then supporting detail and history.

5Actions

Consequential actions follow one path.

Inspect Impact Reason Approval Execute Outcome
  • Only permitted, backend-supported actions appear enabled.
  • Approval needs are labelled before the click.

6States

Every list and record handles:

  • Empty, loading, restricted, stale, unavailable.
  • Unknown payment outcome shown as unresolved, never success.

Borrowed

Shadcn Admin sidebar and header, data-table toolbar, saved views, pagination, settings layouts, command search.

Not imported

Its router, auth, demo data, chart dashboards, generic CRUD, duplicate primitives and neutral palette.

Static kit. Fixture people, references and amounts continue the Cool Again example. Navigation items and buttons are inert specimens; no route, permission or payment behaviour is implied. Supersedes the dark admin specimens (admin-ui-kit, triage, inspector, hold console) for visual direction.
